# 3 分钟产品试用

## 用户旅途

1. 用户浏览 Meeting Setup，点击 Start Meeting 后看到邀请码弹窗。
2. 有码用户沿用原来的验证流程；新用户可点击「Try free for 3 minutes」。下面说明无需邀请码、连接成功开始计时、暂停仍计时。
3. 先完成麦克风授权和检查，这段时间不扣试用时长。授权取消或连接失败后，可用同一份资格重试。
4. 服务端收到翻译连接的 `session.updated` 后开始 180 秒倒计时。Web 显示蓝色 Trial 时间标记，最后 30 秒转为琥珀色；小程序同样显示剩余时间。
5. 暂停、网络重连、刷新后继续同一场试用，都沿用原来的截止时间；不能通过这些操作获得新的 3 分钟。
6. 到期后服务端关闭翻译连接，两端停止收音并保存已收到的会议稿。主动 Stop 也结束本次资格。
7. Web 展示「Your trial is complete」邀请码弹窗；小程序在结果页提供「输入邀请码继续」，返回后打开邀请码弹窗。再次试用按钮禁用；验证邀请码后进入正常会议。

试用入口采用浅蓝色次级按钮，与蓝色邀请码主按钮区分。继续浏览仍放在弹窗最底部；手机短屏可滚动弹窗。验证码保存重试场景不展示新试用入口，避免覆盖上一场会议稿。

## 轻量防重复与边界

- 不增加实名、账号注册、设备指纹或长期试用用户表。
- 复用现有匿名浏览器/小程序客户端 ID；有微信身份时按同一 OpenID 计一次。
- 服务端内存记录保留 6 小时并清理；服务重启会清空。清理浏览器标识或更换客户端可能重新试用，这是当前轻量体验方案的边界。
- 同一客户端重复领取返回同一份尚未结束的资格；结束后返回 409。领取接口还有短期 IP 限流。
- 每份资格只绑定一个会议 ID。准备阶段最多保留 15 分钟；开始后只给 180 秒。
- 超时后保留 10 分钟的会议稿保存窗口，但不能再连接翻译。一份试用只保存一份会议稿，重复保存返回原结果；保存失败可重试。
- 试用凭证不能访问管理接口，也不会消耗邀请码额度。
- 仅在原本需要邀请码的服务模式中开放；无认证的本地开发模式保持原有行为。

## 配置和验证

环境变量 `CHESTNUT_TRIAL_SECONDS` 默认 180，0 关闭试用，最大 900。使用进程环境变量设置后重启服务；本地 `.env` 加载器仍只读取百炼凭证。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
node --test tests/test_access.cjs tests/test_languages.cjs
.\.venv\Scripts\python.exe scripts/verify_trial_browser.py
```

浏览器验收使用临时数据库、虚拟麦克风及模拟翻译服务，通过推进服务端测试时钟验证完整的 180 秒额度与到期行为，不调用百炼、不修改用户数据。截图位于被 Git 忽略的 `test-results/trial/`。
